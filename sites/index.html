FAQ

Questions You Might Have

Here are answers to the most common questions about Devo.

What's the difference between Devo and Cursor / GitHub Copilot?

Copilot/Cursor are code completion/inline editing tools that require you to guide step by step. Devo is an autonomous coding agent: you say one requirement, it plans, writes files, runs commands, reads errors, and loop-fixes — the entire process needs zero line-by-line involvement from you. Simply put: Copilot is a co-pilot, Devo is the driver who drives for you (you hold the brake).

Will code and chat data be uploaded to the cloud?

Absolutely not. Devo's core runs 100% on your local dev machine, directly accessing your local filesystem and shell. All sessions, code, and memory data are stored in the ~/.devo/ directory. The only external communication is your own configured LLM API calls (sending prompts, receiving completions), and optional team services (only stats reporting, zero content upload).

Which LLMs are supported?

Any API compatible with the OpenAI Chat Completions format works. Including but not limited to: GPT-4o / GPT-4o-mini, Claude series (via compatible gateway), DeepSeek, Qwen series, GLM series, Ollama local models, etc. You can configure multiple models and switch anytime.

What is the approval gate? Will it be cumbersome?

Devo categorizes operations into High/Medium/Low/No risk levels. By default, file writes and command execution require your approval (with diff previews). Once you're comfortable, you can:

  • Relax approvals by risk level (e.g., auto-approve low risk)
  • Auto-approve via directory whitelist
  • Enable YOLO mode for full automation (recommended when Git state is committed)
Is it free? Can I use it commercially?

Devo uses the MIT open-source license, completely free to use, including for commercial purposes. You only need to cover your own LLM API costs. In the future there will be optional paid team services (instance management, auditing, quotas, etc.), but the local core will remain permanently open-source and free.

What is MCP extension? How to integrate it?

MCP (Model Context Protocol) is an open protocol that enables AI to dynamically discover and call external tools. Devo natively supports MCP — just configure an MCP Server startup command in the settings panel, and AI can automatically call all tools it exposes. Integrate Feishu docs, databases, internal API gateways, etc. — unlimited capability expansion.
